# TradingSpringCloud 註解規範

> 權威：EngineeringOS `eos-minimal/knowledge/comments.md` @ 0.1.5  
> 本專案宣告：`comment_verbosity: detailed`

## 為什麼是 detailed？

本專案是 **Gateway 代理 vs Feign 聚合** 教學，註解要讓初學者看懂：

1. **【職責】** 這個型別／方法在業務上做什麼  
2. **【技巧】** 用了哪個框架／API／模式（Gateway MVC、`@FeignClient`、RouterFunction…）  
3. **【概念】** 為什麼這樣寫、和替代寫法差在哪（代理轉發 vs 應用層聚合）  

一般純業務專案可改為 `brief`，避免註解過長。切換方式見公版 §7。

## 套用範圍

| 路徑 | 深度 |
|------|------|
| `*/src/main/java/**` | detailed（public 類別／業務方法） |
| `*/src/test/java/**` | detailed（檔頭＋CASE／Given-When-Then） |
| `scripts/*.ps1` | 檔頭用途／何時跑／成功標準 |
| 簡單 getter／setter | 一行或併入類別說明，勿灌水三段 |

## 檢查

- [x] 每個 public 型別有【職責】【技巧】【概念】（getter 可合併在類別說明）
- [x] Gateway／Feign／Service／Controller／Config 的 public 業務方法含三段式
